# Xometry US quote-only workflow

Use for an authorized browser quote for the exact requested configuration. Read [observed DOM and evidence](references/observed-dom-and-evidence.md) before acting. This skill does not authorize another upload or resolve an existing uncertain intent.

As checked on 2026-10-23, `backend/app/modules/cnc/quote/providers.py::resolve_quote_adapter()` returns `None`. Keep production activation unchanged; this skill does not establish application automation or provider acceptance.

## Controlled flow

1. **Freeze the request and file.** Bind the authorized actor/account, platform, configuration and linked part to a run. Record process, material, finish, quantity and all extra parameters. Check third-party upload authorization, trusted-root path containment, current STEP content/extension and size limits. Read the exact payload once and verify its filename, byte length and SHA-256 against the frozen source; upload those same immutable bytes or a verified protected copy. Stop if the source changes or cannot be verified. A matching filename or `.STEP` extension is insufficient.
2. **Verify identity and ownership.** Attach only the authorized Xometry US session on trusted configured HTTPS hosts. Resolve the actual platform record and configured entry, never a hardcoded platform ID. The existing provider verifies explicit email fields through `https://api.xometry.com/v2/users/me` in the guarded page/context. Confirm the exact intended account; visible initials, dashboard presence and cookies alone are insufficient. Return only a match result or masked identity. Reuse valid login; let the user handle credentials/challenges through normal UI when needed. Pause automation during human input and reverify identity on the same quote page without navigating away or losing configuration. Stop on account mismatch, unavailable verification, competing browser ownership or off-policy navigation.
3. **Guard mutations with durable intents.** Before each upload, parameter save/apply or quote request, persist its run/account/file-hash/parameter-generation/operation identity and claim in the existing authorized intent store or private task log. If durable recording is unavailable, stop. Repeated requests reuse the existing operation; reconcile the receipt and remote part/quote identity before proceeding. Timeout, cancellation, restart or failed confirmation leaves the outcome uncertain: use bounded read-only reconciliation, then stop if unresolved. Never clear a claim to retry. Preserve the earlier uncertain upload described in the reference; do not replay it or replace it with a new run to evade reconciliation.
4. **Upload only after reconciliation permits it.** Inspect current DOM and use the official file-input/chooser helper once with the verified payload. For an already-staged matching upload, continue from reconciled state without uploading again. Observe classification and remote part identity before continuing. Capture fresh, scoped DOM observations before and after each transition; use newly observed controls and references.
5. **Stop at the export declaration unless explicitly decided.** ITAR/EAR/CUI/export-control selection and Continue require an explicit user decision recorded for the exact frozen file and displayed declaration within this quote-only scope. Record file hash, choice, scope and decision time privately. Never infer classification from extension, filename, origin, a prior different file or a default. If authorization is absent or ambiguous, leave the declaration untouched and report the blocker. Apply an already recorded exact-scope decision without asking again.
6. **Configure and verify effective values.** Establish which page variant is open before choosing controls: the public test drive, historical quote's `vercel_part_config=test` route and normal managed quote are separate evidence scopes. The reference supplies observed configuration candidates, including the material search popup; they are not enabled runtime bindings. Locate the current control uniquely by its semantic name and observed attributes, inspect its options, and match the exact material option title rather than the entire description or a substring. Re-observe dependent options after process/material changes. Treat **Save Configuration** as a separate mutation with its own durable intent; after it completes, read back saved effective process, material (including temper/product form), finish, quantity and every applicable extra parameter. Bind remote part/positive geometry to the upload receipt. Unknown keys, unsupported/ambiguous mappings, incomplete parsing or any mismatch stop the flow; never substitute or omit parameters. Saved-value readback and price extraction still require live verification.
7. **Read a fresh quote and stop.** Inspect the current action's semantics before any quote request; unclear side effects stop execution. Verify the result belongs to this run, remote part and parameter generation after recalculation finishes. Record quote/part identifiers, raw status, decimal amount, explicit currency evidence, price basis (unit/subtotal/total and its scope), quantity, raw lead-time text, requested/effective values and observation time. Old/cached prices, another quote or missing currency/basis cannot satisfy a new quote. Stop before **Checkout**, **Order**, **Forward to Purchaser**, payment or equivalent commitments.

## Result interpretation and evidence

- **QUOTED**: fresh same-run quote for the verified file/positive geometry and all effective parameters, with a positive finite decimal-string amount, explicit interpretable currency and price basis, and known lead-time context preserved in the platform's wording.
- **REFERENCE_ESTIMATE**: explicitly labeled estimate/reference amount; retain that qualification.
- **PENDING_REVIEW**: explicitly awaiting manual review; no completed quote claim.
- **FAILED**: known rejection or validation failure; report the observed reason without a fabricated price.

An unresolved declaration, identity or mutation receipt is a blocker with no verified quote; preserve the intent's uncertain state. Keep raw platform status and lead time, and never infer an ISO currency solely from `$`. Report verified observations, remaining blockers and incomplete acceptance accurately.

Store minimal redacted evidence in the authorized private run/task record. Never expose credentials, cookies, tokens, signed file URLs, credential-bearing headers or auth storage. Scope DOM capture to relevant visible content, omit sensitive values/URL attributes, and sanitize screenshots before retaining them.
